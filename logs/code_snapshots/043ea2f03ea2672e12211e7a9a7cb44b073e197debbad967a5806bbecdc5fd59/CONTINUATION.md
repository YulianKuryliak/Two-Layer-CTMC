# Продовження поточного chain запуску швидшою версією

У терміналі поточного запуску натиснути Ctrl+C і дочекатися виходу runner та його workers. Залежно від завершення активних задач це може зайняти час. Новий запуск перевіряє блокування старої папки та відмовляється працювати одночасно зі старим runner.

З кореня проєкту виконати:

```bash
.venv/bin/python optimization/continue_chain_v2.py --run --workers 10
```

Джерело: `output/chain_twoscale_residual_midpoint_20261007`.
Продовження: `output/chain_twoscale_continued_v2_20261008`.
Ці шляхи можна задати через `--resume-from` і `--output`; підтримується лише перевірена початкова residual-midpoint версія та незмінне середовище.

Запуск перевіряє старий manifest, заморожені вихідні файли, відбиток перевіреної оптимізації, тотожність задач/seed/горизонтів і повноту checkpoint. Завершені checkpoint зберігають початкові байти, версію й відбиток коду. За можливості створюються жорсткі посилання без дублювання 2+ ГБ даних, інакше незалежні копії. Старі й імпортовані checkpoint слід залишати незмінними.

`continuation.json` окремо фіксує джерело, початкові хеші та імпорт кожного файла; наукові результати не переписуються під нову версію. Папка продовження містить усі завершені checkpoint: старі з явним походженням і нові, обчислені оптимізованою копією graph_build_v2. Full повторно не моделюється. Зміни runner адаптера також включені в новий code fingerprint.

Незавершені траєкторії починаються заново з тих самих seeds. Checkpoint посеред окремої траєкторії не існує. Подальші переривання/продовження виконуються тією самою командою: імпорт і нові завершені задачі перевіряються та пропускаються.

За потреби лише підготувати й імпортувати результати без симуляцій:

```bash
.venv/bin/python optimization/continue_chain_v2.py --prepare-only
```

Не запускати стандартний v2 runner без цього адаптера на папці продовження: змішане походження checkpoint обробляє саме адаптер. Після редагування його коду потрібна нова папка результатів.

Перевірка адаптера без моделювання:

```bash
.venv/bin/python optimization/verify_continuation_v2.py
```

Перевірено незмінність байтів/початкового відбитка, повторний імпорт, відхилення змінених задач і пошкоджених checkpoint, відсутність незавершених checkpoint, нову provenance для нових результатів, блокування активного джерела та серіалізацію worker-функції. Основна симуляція не запускалася адаптером під час підготовки.
