# Оптимізація підготовки графів, v2

Окрема копія перевіреної `optimization/state_events_v1/optimized`:
`baseline/` зберігає її без змін, `optimized/` містить новий будівник.
Початковий код проєкту, v1 та вже запущений основний розрахунок не змінені.
Хеші вихідних файлів записані в `snapshot_manifest.json`.

## Що змінено

- Для заморожених входів chain TwoScale сусіди та ваги формуються без проміжного повного NetworkX-графа й повторного додавання його ребер у MicroModel. Графи станів вузлів залишаються.
- Декодування gzip/JSON і локальна топологія кешуються окремо в кожному процесі: не більше двох шаблонів. Кожна спільнота отримує незалежні масиви; стан моделювання не кешується.
- Збережено порядок обходу NetworkX, останню вагу повторного ребра, позицію його першого додавання, обробку петель і кратність інтерфейсів. Непідтримувані входи повертаються до попереднього будівника.
- Зміни алгоритму зосереджені в `engines/frozen_topology.py`, `orchestrators/micromacro.py` та скопійованому `rerun_chain_twoscale.py`.

Швидкий будівник призначений лише для цього chain TwoScale runner. Його службовий граф містить метадані, але не фізичні ребра; він не є заміною графа для Full Gillespie або довільних NetworkX-операцій. Full читається з попередніх результатів, як у v1.

Кеш розрахований на незмінні заморожені входи. SHA-256 перевіряється під час завантаження нового шаблону; ключ кешу включає шлях, очікуваний SHA, кількість вузлів та файлові атрибути, зокрема час зміни. При попаданні в кеш файл повторно не хешується. Зміна файла зі збереженням усіх атрибутів або конкурентне редагування входів не належать до цього контракту.

## Перевірені результати

Повний звіт: `output/graph_build_validation_20261008T060754957150/summary.json`;
параметри, seeds і хеші: `manifest.json` у тій самій папці.
Відбиток перевіреного коду:
`66cbdb5a9d36a8aa6de6a429f167990fdbfd884a781447f9763f9fcab19f292a`.

Усі 57 синтетичних перевірок пройшли, включно з 42 траєкторіями SI/SIR/SIS, порядком топології, дублікатами, петлями, ізольованими вузлами, незалежністю масивів, кешем і fallback. Також пройшли 10 наявних регресій та 4 повні повтори збережених задач: щільна, розріджена, задача з різними горизонтами Full/TwoScale та щільна n250.
Порівнювалися всі події, стани, відкладені пропозиції й RNG; числа порівнювалися точно через `float.hex`. Наукові поля результатів збігаються з v1 і збереженими виправленими результатами; службові час, версія та runtime виключені з порівняння.

Для 10 щільних спільнот по 250 вузлів, медіана трьох повторів підготовки топології та моделей:

| Показник | v1 | v2 |
|---|---:|---:|
| Підготовка, холодний кеш | 1.599 с | 0.193 с (8.30×) |
| Підготовка, прогрітий кеш | 1.599 с | 0.153 с (10.46×) |
| Пік виділень, виміряних tracemalloc | 113.62 МіБ | 15.05 МіБ |
| Живі виділення перед симуляцією | 12.23 МіБ | 13.02 МіБ |

Пік виміряних виділень зменшився приблизно на 87%; це не вимір усієї оперативної пам'яті процесу. Невелике збільшення живих виділень пов'язане з кешем шаблонів. Виміри пам'яті отримані в окремих трасованих процесах.
Прискорення 8–10× стосується підготовки. Ядро симуляції залишається з v1; у малих задачах n50 загальний час був близьким або трохи більшим під поточним навантаженням CPU. Ці чотири повтори не є перевіркою всіх 19 200 задач.

## Запуск

Повторити обмежену послідовну перевірку в новій папці результатів:

```bash
.venv/bin/python optimization/graph_build_v2/validate.py
```

Запуск нової повної серії користувачем:

```bash
.venv/bin/python optimization/graph_build_v2/optimized/extrascripts/runners/rerun_chain_twoscale.py --run --workers 10
```

Нова версія: `chain_twoscale_graph_build_optimized_v2`;
нова папка: `output/chain_twoscale_graph_build_v2_20261008`.
Повна серія цією зміною не запускалась. Попередні результати не перезаписуються; перевірки й runner ведуть журнал експериментів.
