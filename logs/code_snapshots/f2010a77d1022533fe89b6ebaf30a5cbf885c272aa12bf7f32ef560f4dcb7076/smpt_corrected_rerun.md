# Повторний запуск експериментів SMPT після виправлення локального годинника

Ранер: `extrascripts/runners/rerun_smpt_paper.py`.
Стаття: `paper/SMPT paper/claude-version_merged.tex`.
Початкова папка результатів: `output/paper_rerun_residual_clock_20261007`.

Повний запуск із кореня проєкту:

```bash
.venv/bin/python extrascripts/runners/rerun_smpt_paper.py --run
```

Ранер сам підготує маніфест, а після переривання ця сама команда продовжить роботу.
Підготовка без симуляцій:

```bash
.venv/bin/python extrascripts/runners/rerun_smpt_paper.py --prepare-only
```

Після підготовки можна перевірити один запуск:

```bash
.venv/bin/python extrascripts/runners/rerun_smpt_paper.py --run --series source_leaf --limit 1
```

Разом **46 000 пар / 92 000 траєкторій**. Для двох історично продовжених Full-запусків із n=50, ASPL=6, k=1 горизонт Full становить 40 000; MicroMacro зберігає 30 000. Ці винятки явно позначені у маніфесті й чекпойнтах. Усі серії SI: γ=0, одиничні ваги, τ=1. Ранер зберігає історичні початкові вузли, фізичні інтерфейси й event seeds.

Source–leaf бере ASPL 1–1.75 із `n1000_random_connected_tree_augmented_aspl1to1p75_step025_rep400_random_initial`, ASPL 2–6 із `n1000_random_connected_tree_augmented_aspl_step025_rep400_random_initial_full_corrected`. Це вже виправлена історична постановка Full із відповідним випадковим початковим вузлом. Clique–leaf бере початкові метадані з `output/main_clean_benchmarks_independent_rng/.checkpoints/clique_leaf_n100_k2`.

Підготовка заморожує список усіх задач, копії графів і вихідного коду, SHA-256 джерельних чекпойнтів, seeds та параметри. Для clique–leaf внутрішній граф — кліка; точні bridge endpoints відновлюються за історичним network seed і зберігаються в задачі. Якщо код або заморожені входи зміняться, продовження відхиляється: треба вибрати нову папку через `--output`.

У кожному атомарному `.json.gz` чекпойнті є повні типізовані події, сумісні `infection_events`, часи прибуття, стан завершення, усі точки зміни S/I/R, кількість успішних імпортів і повторних імпортів у вже заражену спільноту. Повтори рахуються окремо за всю збережену траєкторію та до T9 / першого зараження листка. Точні часи й стани не округлюються та не ресемплюються. Макроімпорт заражає нового сприйнятливого вузла в спільноті, де вже є заражені.

Політика локального годинника: `residual_intensity_budget_v1`. Використовується штатний `Orchestrator`, з окремим RNG для кожного MicroModel; підміни clone/refresh немає. Після імпорту збережений залишок інтегрованої інтенсивності переводиться у новий час за оновленою сумарною локальною інтенсивністю.

Нехай стара мікроподія була запланована на `t_old`, імпорт відбувся в
`t_import`, сумарна локальна інтенсивність змінилася з `a_old` на `a_new`.
Тоді `B_remaining = a_old * (t_old - t_import)`, а
`t_new = t_import + B_remaining / a_new`. Це бюджет сумарного локального
годинника (зараження плюс одужання), а не окремий бюджет кожного ребра.
Тип і ціль наступної події вибираються заново. Якщо нова інтенсивність нульова,
бюджет призупиняється; якщо до імпорту не було активного годинника, стартує
новий експоненційний бюджет. RNG після відкинутої мітки не відкочується.

Midpoint-планувальник із τ=1 залишається наближеним: ця зміна не усуває його
похибку інтегрування або використання стану з майбутньої середини інтервалу.
Рівномірне розміщення імпорту та агреговані міжспільнотні інтенсивності також
збережено. Нові результати оцінять сумарний ефект технічних виправлень, а не
лише ефект однієї формули за незмінного RNG і кешування.

За замовчуванням виконується одна пара за раз. `--workers N` явно задає паралельність для інших конфігурацій; щільні ланцюги клік завжди запускаються послідовно через споживання пам’яті. Блокування папки забороняє два одночасні ранеры. `run_status.json` розрізняє підготовку, повне завершення, завершення підмножини, помилку й переривання.

Події підготовки, старту, завершення кожної пари, пропуску під час resume і помилки пишуться у `experiments.jsonl` цієї папки та у центральний `logs/experiments.jsonl`. Історія коду: `history.md` і `logs/code_changes.jsonl` із SHA-256 та копіями змінених файлів. Історичні результати й revised-стаття не перезаписуються.
