# Чорна двомовна редакція секцій 1–3 на основі parallel-версії

Основний PDF: `../claude-version_merged_bilingual_UK_EN_plain_sections_1_3_black.pdf`.
Англійська версія ліворуч, українська праворуч. Текст секцій 1–3 чорний.
Природні кольори вузлів рисунка означають їхні епідемічні стани.

За основу взято `claude-version_merged_parallel_EN.tex` та
`claude-version_merged_parallel_UK.tex` з відповідними українськими частинами.
Рисунок 1 використовує саме TikZ-схему з цих джерел, однакову в обох мовах;
старий файл `Images/twoscale/fig_method_schematic.pdf` не підключається.
Геометрія та написи схеми збережені, підпис пояснює її три панелі простіше.

Додаткові зауваження читача доопрацьовано так:

| Зауваження | Зміна в секціях 1–3 |
|---|---|
| Чи є дві реалізації? | Експерименти використовують одну реалізацію з часовою сіткою. Ідеальний процес є теоретичним описом для розділення похибок. |
| Чи відповідає годинник MoMLeT? | Пояснено спільний принцип накопичення інтенсивності, оцінку в середині кроку та збереження залишкового локального порога. Деталі перевірено за локальним PDF конференційної роботи, с. 6–9. |
| Що таке `inf`, `E` та накопичена величина? | Збережено просту рівність інтеграла й порога, явно пояснено перше досягнення. Значення `E` та `A` повторено біля формули оцінки часу; додано числовий приклад. |
| Як вибирається вузол? | Спочатку вибираються спільноти, потім один сприйнятливий вузол рівномірно. Для 20 вузлів кожен має імовірність 1/20; пояснено позначення `Pi`. |
| Чи справді є економія? | Прибрано безумовну заяву про економію пам'яті. Пояснено залежність від кількості міжспільнотних ребер і витрати на копіювання станів. |
| Чи можливе розпаралелення? | Локальне просування можливе паралельно до вже визначеного спільного часу, із подальшим збором станів та імпортом. Поточну реалізацію описано як послідовну; прискорення не заявлено. |

Збережено всі 25 бібліографічних цитувань у секціях 1–3, 18 міток і
шість номерів формул у кожній мові. Анотацію, highlights, секції 4 і далі,
бібліографію та інші рисунки не редагували. Числові результати залишаються
результатами базової parallel-версії; нові результати перезапуску тут не підмінялися.

Попередня червона редакція та всі базові файли збережені. Їхні додаткові
копії знаходяться в `originals/`, контрольні суми — в `originals_manifest.json`.
Відомості про сторінки та перевірки — у `build_manifest.json` і `verification.json`.

Збірка з кореня репозиторію:

```bash
.venv/bin/python extrascripts/analysis/build_smpt_readability_parallel.py
```

Скрипт перевіряє незмінність базових файлів, цитувань, міток, номерів формул
і TikZ-схеми. Він збирає мовні PDF та вирівнює початки секцій у двомовному
документі. Це лише збірка LaTeX, без запуску симуляцій.
