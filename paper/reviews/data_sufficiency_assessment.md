# Оцінка достатності даних: коли і як відрізняються Micro та MicroMacro

**Дата:** 31 липня 2026
**Питання:** Чи достатньо наявних експериментів і метрик, щоб зрозуміти, *коли* і *як* дві моделі відрізняються, і сформувати висновки? Чи потрібні ще експерименти/метрики?

---

## 1. Стисла відповідь

| Питання | Статус | Коментар |
|---|---|---|
| **ЯК** моделі відрізняються (механізм, напрямок зміщення) | ✅ **Достатньо** | Механізми декомпоновані (CE-01), напрямок доведено аналітично (Jensen) і підтверджено RMST |
| **КОЛИ** моделі відрізняються (передбачуваний критерій) | ⚠️ **Частково** | Є OFAT-свіпи, але немає кількісного a-priori критерію та карти взаємодій |
| **Чи метод можна виправити** | ❌ **Немає даних** | EXP-05 (bridge-aware correction) не виконано — це критична прогалина |
| **Достатньо для висновків?** | ⚠️ **Для «biased» — так; для «fixable approximation» — ні** | Стаття робить обидва твердження, друге не підкріплене |

**Вердикт:** Наявних даних достатньо, щоб стверджувати, що MicroMacro *систематично зміщений* і *описати механізми*. Їх **недостатньо**, щоб (а) дати практику передбачуваний критерій точності, (б) стверджувати, що метод *піддається виправленню*. Потрібно **2 цільові експерименти** і **1 виправлення метрики**, перш ніж закривати Results.

## 2. Що вже покрито (сильні сторони)

### 2.1 Механізм помилки — декомпоновано (CE-01)
Факторний ablation розділяє повну помилку на:
- **rate abstraction** (домінує): ΔRMST = −208.8, CI [−310, −112]
- **import placement** (значимий лише за точного hazard): −168.8
- **interaction** (super-additive): +149.2

Це відповідає на «ЯК»: основне джерело — агрегація hazard, а не розміщення.

### 2.2 Напрямок зміщення — аналітично + емпірично
- Jensen-нерівність $S^{\text{Micro}} \geq S^{\text{Macro}}$ доведена строго
- Підтверджена RMST у сценаріях зі 100% completion (k=10, k=20: CI виключає нуль)
- Артефакт conditional-median пояснений (див. `jensen_violation_analysis.md`)

### 2.3 Однофакторні свіпи — 6 вимірів параметрів
| Вимір | Свіп | Джерело | Ключовий результат |
|---|---|---|---|
| Interface width $k$ | {1,5,10,20} | clique + sparse | більше $k$ → більше абс. помилки, але вище completion |
| Internal density $d$ | {4,6,10} | sparse | вище $d$ → менше помилки (не зникає) |
| Chain length $L$ | {5,10,15} | clique | довший → більша абс. помилка |
| Community size $n$ | {50,100,200} | clique | слабкий ефект |
| **Beta ratio $r$** | {0.1,0.3,1,2,5} | CE-03 | **зміна знаку** між 0.3 і 1.0 |
| **Recovery $\gamma$** | SI, R₀={6,3,1} | CE-04 | recovery погіршує; 44 в.п. хибних completion при R₀=1 |
| Topology | complete vs sparse | обидва | sparse дає ~43% rel-W₁ |

### 2.4 Метрики — коректний цензуро-стійкий набір
RMST/ΔRMST, rel-W₁, completion rate, paired per-hop error, survival curves з bootstrap CI. Це правильний фундамент (див. `report_metrics_guide.tex`).

## 3. Прогалини (чому «частково»)

### 3.1 КРИТИЧНО: немає кількісного критерію придатності
Усі свіпи — **one-factor-at-a-time (OFAT)**. Практик не може передбачити помилку a priori, бо:
- Немає формули/порогу типу «rel-W₁ < 10% якщо $r \in [a,b]$ **та** $d > d^*$ **та** $k/n > c$»
- Взаємодії між $k$, $d$, $r$, $\gamma$ **невідомі** (крім rate×placement у CE-01)
- Наприклад: чи зберігається зміна знаку CE-03 при $\gamma > 0$? при різних $d$? — невідомо

Це вже зазначено у критичній рецензії (Section 3.2). Без цього стаття не відповідає на власне дослідницьке питання «в яких режимах апроксимація мала?».

### 3.2 КРИТИЧНО: EXP-05 (correction ceiling) не виконано
Стаття у Conclusions стверджує, що bridge-aware hazard «would preserve the main computational advantage while reducing the dominant source of interface bias». **Це твердження не підкріплене жодними даними.**

Без EXP-05 (Full Micro | MM-uniform | MM-oracle-bridge | MM-degree-weighted) неможливо стверджувати, що метод *піддається виправленню*. Наразі дані показують лише, що метод *зміщений*. Це різниця між «перспективний метод з відомою корекцією» і «неправильна модель для класу задач».

**Це найважливіша відсутня частина для публікації.**

### 3.3 МЕТОДОЛОГІЧНО: CE-03 конфаунднутий горизонтом
CE-03 використовує **різні** $T_{\text{end}}$ для різних $r$:

| $r$ | $T_{\text{end}}$ | ΔRMST |
|---|---|---|
| 0.1 | **20000** | +4796 |
| 0.3 | 10000 | +562 |
| 1.0 | 4000 | −1355 |
| 2.0 | 3000 | −1638 |
| 5.0 | **2000** | −1213 |

Горизонт змінюється у **10 разів**. Оскільки RMST обмежений $T_{\text{end}}$, величини ΔRMST **не порівнювані** між рядками (порушує правило AGENTS.md: «Do not compare results across different horizons as if they were the same experiment»).

- **Знак** зміщення валідний (це якісний результат).
- **Величина** і твердження про «crossover $r^*$» — конфаунднуті. +4796 при горизонті 20000 не можна ставити в один ряд з −1213 при горизонті 2000.
- Потрібна горизонто-незалежна метрика (напр. ΔRMST/$T_{\text{end}}$, rel-W₁, або відношення медіан) для чесного порівняння по $r$.

### 3.4 Статистична потужність недостатня в clique-режимі
З `report_metrics_guide.tex`: clique baseline ($k=5$) потребує **~480 replications** для виявлення ΔRMST=−75.6; виконано лише 100. Тому кілька ключових CI включають нуль (baseline, L=5, n=200). Це створює хибне враження «немає ефекту», хоча насправді бракує потужності.

### 3.5 EXP-02 (gateway distance) не виконано
Механістичний предиктор rate-abstraction помилки — внутрішня відстань між import/export граничними вузлами $D_{\min}$. Без нього декомпозиція CE-01 не має структурного предиктора «наскільки погано» для конкретної топології. Це *бажано*, але не блокує (на відміну від 3.1–3.2).

### 3.6 Placement error не ізольований у мережевих бенчмарках
CE-01 ізолює placement лише на одній конфігурації. У основних chain-бенчмарках внесок placement vs rate не розділений per-hop.

## 4. Аналіз метрик: чи потрібні нові?

Наявний набір метрик **достатній за складом**, але потребує **2 доповнень**:

### 4.1 Потрібно: горизонто-нормалізована метрика
Для крос-$r$ і крос-$\gamma$ порівнянь (де $T_{\text{end}}$ різний) додати безрозмірну:
$$\widetilde{\Delta} = \frac{\Delta\text{RMST}}{T_{\text{end}}} \quad \text{або} \quad \text{rel-W}_1 \text{ (вже є, використати як primary для CE-03)}$$

### 4.2 Потрібно: completion-probability error як first-class метрика
Найяскравіший результат (CE-04: 44 в.п. хибних completion; CE-03: 99 в.п. при r=5) наразі подається як побічний коментар. Варто зробити:
$$\Delta p = p_{\text{complete}}^{\text{MM}} - p_{\text{complete}}^{\text{Micro}}$$
first-class метрикою з bootstrap CI. Це метрика *якісної* різниці (метод передбачає епідемію там, де її немає) — найважливіша для практика.

### 4.3 Не потрібно
KS, нові distributional distances — надлишкові. RMST + rel-W₁ + paired per-hop + Δp покривають усе.

## 6. Висновок

**Для поточного (акуратного) наративу «MicroMacro систематично зміщений, і ось механізми» — даних достатньо.** CE-01/CE-03/CE-04 + calibrated/sparse бенчмарки надійно встановлюють:
- напрямок зміщення (Jensen, підтверджено RMST),
- домінантний механізм (rate abstraction),
- зміну знаку за низького $r$,
- погіршення за recovery,
- якісний збій (хибні completion).

**Для повного наративу «коли метод точний і як його виправити» — даних недостатньо.** Бракує:
1. кількісного критерію придатності (пункт 2),
2. доказу, що корекція працює (EXP-05, пункт 1),
3. коректного крос-$r$ порівняння (пункт 3).

Без пунктів 1–3 стаття змушена обмежити claims до «метод зміщений, ось діагностика», прибравши з Conclusions твердження про «reducing the dominant source of bias» як непідкріплене. Це прийнятний, але слабший результат.

**Рекомендація:** виконати переаналіз (пункти 3, 4 — швидко, без симуляцій), побудувати regime map (пункт 2), і запустити EXP-05 (пункт 1) — після цього результатів достатньо для сильної публікації з повним циклом «діагноз → критерій → виправлення».
